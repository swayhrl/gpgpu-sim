## 1. Attached A0 duplicate merge

**Observed fact:** A's retained r34 GDB capture shows A0 slot146, attached=1, reuse_seen=1, required=15, issued=15, ready=0, waiters=5. The caller's before=20 and current ro_packets=20, ro_bytes=640 are recorded. It aborts at submit_ro(0), main:134 after withholding all RO returns. The diagnostic does not record all child UIDs or a payload generation, so C does not invent them. It is controlled symbolic cache/partition evidence, not native DRAM/SASS or a completed application.

**Source deduction:** Core27 runtime target() uses the live attached Tag/landing first, or the ordinary line record only when M is off. merge_existing() does not reject reuse_seen. After successful shared descriptor reservation, merge() appends that requester and ORs its mask. Scheduled sectors are required|ready; needed is request_mask & ~scheduled. Transaction lower_needed is required & ~(issued|ready). For captured A0 both forms yield zero new sector work for a sector0 duplicate. It correctly creates another descriptor/waiter on the same landing and emits no new lower packet. reuse_seen prevents detach; it does not prevent merging or require a fresh data fetch.

Admission still requires the certified full epoch, global demand read class, exact Tag generation/landing binding, D512 capacity and address cap32. A rejected request (wrong kind/epoch/proof/binding, no descriptor, or repeated pointer already allocated in D512) does not set reuse_seen or append a waiter. A separate same-line request is not the same mem_fetch pointer.

## 2. Exact reuse_seen lifetime and conservative limit

**Source deduction:** entry() initializes false. Successful admit assigns e=entry() after line/descriptor/pin admission succeeds. The only explicit assignment to true is after successful merge descriptor reservation. It is set by any successful merge: another sector, the same sector, another parent, or a sibling of the same split parent. It does not check original_mf or distinguish semantic parent reuse from sector siblings. It can be set for a ready-sector waiter too.

Both can_detach() and detach() require T enabled, attached, !reuse_seen and at least one required sector not ready. detach() additionally verifies the exact Tag/landing generation handshake. Under pressure the runtime scans the requested set in Tag-index order and selects the first eligible transaction; A0 is not a privileged detach victim. It does not choose LRU among all RO transactions.

Fill, successful/denied response, removing a merged waiter, and Tag detach do not clear reuse_seen. retire_if_done() sets live=false after all waiters, response preparation, required sectors and issued sectors are done; it leaves the old bit in the inactive entry. Only the next successful admission into that slot resets the whole entry. Retirement of an attached landing returns it to ordinary resident ownership. That resident can later be replaced normally; the sticky bit is not a permanent prohibition on reuse of a physical Tag.

**Real conservative restriction:** a full 128B parent becomes four independently admitted 32B requesters. With no return between them, child0 admits and child1 immediately makes reuse_seen sticky, even though there was only one semantic parent. The transaction cannot detach while its fills or requesters remain live. Protection also persists when a merged waiter has retired but other work remains. Thus T can be less effective on multi-sector traffic, and a set of only such protected pending owners can stall a conflicting request. This is a source-level performance limitation of the frozen policy, not observed application slowdown or a correctness failure. Exempting siblings or clearing the bit early would change policy and needs separate scientific review; neither is part of this delivery.

## 3. Parent, child, descriptor, landing and response mapping

**Source deduction, with exact anchors in CONTROL_CHECKS.json:**

| Object | Identity and lifetime |
| --- | --- |
| Input 128B parent P | One allocated UID (275 in the GDB capture). P is not itself put in the subpartition request tracker or RO descriptor pool after splitting. Retain it in the fixture while children can reference it. |
| Four 32B requester children C0..C3 | Allocated by breakdown_request_to_sector_requests, addresses P.addr+32*s, one-hot mask1<<s, distinct new UID, original_mf=P, inherited warp/shader/TPC/stream. All are tracked and accepted separately by the real frontend. |
| Shared D512 requester descriptors | One for each accepted child, storing that exact child pointer/mask and descriptor generation. Child0 admits; later children merge onto the attached landing. A separate sector0 duplicate adds a fifth descriptor. No parent descriptor or second private requester pool. |
| Landing H | Paid 128B payload_id+generation, one transaction in the payload-indexed slots, one pin per transaction, aggregate required/issued/ready masks. Attached Tag binding also has an independent Tag index/generation. In M=1 no conventional line record is allocated. |
| RO lower packets L0..L3 | Separately allocated new UID, no original_mf parent pointer, ro_lower_packet flag, one-hot sector mask, exact H and generation. They copy valid requester wid/sid/tpc/stream and route identity. These are neither P nor C0..C3 and consume no additional requester descriptors. |
| Lower return | Uses Ls UID as native FILL bank client and H/generation/mask as obligation. A denied grant retains the real ReturnQ packet. Successful accept writes only selected sectors then deletes the lower packet. It never answers P directly. |
| RO response | Chooses the original requester from D512; RESPONSE bank client uses Cs UID (or the duplicate's UID). Choice is held across denied grant/retry. Enqueue to the actual L2->ICNT queue frees that descriptor; pop delivers the child, not an assembled parent. |

For this recorded no-return prefix, four A0 children +16 singleton lines +one duplicate means **21 inferred RO descriptors**, not18. A0 accounts for5 of them and its original request is still attached. There are **20 observed RO lower packets/640B**, not a completed22/704B result. The initial native warmup adds one lower read, separate from RO. Original planned22 total assumed another RO packet which never issues.

The original expected map registers P's UID, but collect() tests the actual child's UID. Once returns start, that reference bookkeeping must track each child (and duplicate) separately; there is no parent response at this boundary. The parent must not be deleted at the first child response. A fixture-only parent owner/counter may free it after all its children have been consumed, without adding any production aggregation, descriptor or data buffer. Partial return3,1,2 can complete those three children; the test must not mistake their absence from the parent UID for lack of completion. Landing release is tied to the last required fill **and actual waiter enqueues**, not to receipt of one final fill or host pop alone.

**Late-return safety, source deduction:** detached old H stays pinned and owns its outstanding sectors; new Tag/landing has a different identity. tx.fill validates the live exact H and pending issue mask; attached fills verify Tag generation. A detached fill calls no Tag-ready callback. It writes old H only. Reused payload generations reject stale handles, and descriptor generations protect reused D512 IDs. Unpin/release waits for all pending work and response enqueues. The corrected joint case must actually observe these invariants; this audit is not a substitute for that run.
